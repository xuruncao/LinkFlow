# 验证范围与结果

## 发布前检查

检查源码与配置中的来源残留、真实凭据、内部路径和提交范围。许可证与来源声明保留，内部交接和简历材料、真实生产配置、地图 key、数据库、消息存储、日志、依赖和构建产物排除。

前端执行 `npm run build`；后端使用 JDK 17 执行 `mvn -B package -DskipTests -Dspotless.apply.skip=true`。该仓库尚无覆盖所有业务路径的自动化测试套件，构建成功不等于完整业务回归。浏览器人工检查本地登录／工作台读取、主题与登录／注册切换；地域 key 缺省时采用代码级降级，不进行外部地图查询。

## 历史渠道归因检查

本地测试覆盖 `wechat / 618`、带空白标点的 `DouYin!!`、缺失 utm 时的 Referer 域名、中文来源和无投放计划时的 `unknown`。单链与分组聚合接口均返回渠道／计划数据；该检查不代表广告平台回传或真实转化归因验证。

## 历史 broker 故障检查

在本地单机环境停止 broker 后，12 次请求均返回 302，中位 11.7 ms；补偿队列累积 12 条。恢复 broker 后，观察到队列约 15 秒内清空，测试数据的访问明细和 PV 从 3 增至 15。同步提交开关的 8 次对照也返回 302。

这些是特定开发环境的小样本故障结果。不能推导任意故障下的零丢失、exactly-once、多实例容灾或稳定生产时延；并非本次发布后重新跑出的压测结果。更多参数与原始实现的限制见 [IMPROVEMENTS.md](../IMPROVEMENTS.md) 和 [RESULTS.md](../scripts/performance/RESULTS.md)。
